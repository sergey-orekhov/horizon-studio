# ADR 0005 — Codex through app-server

Status — accepted for issue #39.

HorizonAgent runs one `codex app-server --listen stdio://` process per Session. Requests, notifications and interactive approvals use newline-delimited JSON-RPC. The Agent dependency pins `@openai/codex` to `0.166.0`, and Agent Update installs that exact version with the rest of the build. No globally installed CLI is required.

The adapter imports protocol declarations generated by the pinned CLI. `npm run generate:codex -w @horizon/agent` regenerates the used declarations and their transitive imports, normalizing type-only imports to `.ts` for NodeNext. A dependency upgrade must regenerate these declarations and pass typecheck and the fake-server tests together.

## Credentials

Login happens on the Agent machine under the Agent's OS user. `npx @openai/codex login` uses ChatGPT, `--device-auth` supports a headless machine, and `--with-api-key` reads an API key from stdin. Codex manages the credential cache. Studio neither receives nor stores these credentials. A short-lived app-server reports readiness and login method through `account/read`.

## Standalone process launch

Each Task uses a separate SQLite index under its Task storage, and status probes use an Agent Home index. During Windows validation the pinned CLI intermittently failed to initialize its SQLite index while sharing it with a running desktop Codex version. The separate `sqlite_home` removed that observed startup failure. This is a local index workaround, not credential isolation: configuration, authentication and rollout files remain in the user's Codex home, preserving CLI login and native thread resume. Indexes are outside the Task Directory so model tools cannot edit them through ordinary workspace writes.

An Agent launched from desktop Codex can inherit that app's private process-launch context. With Codex 0.166.0 on Windows, tools then failed with `registered Core launch requires an installed app`. `codexEnvironment` removes the known app launch, sandbox registration and parent-turn variables from a copy of the child environment. Public user configuration and credentials, including `CODEX_HOME` and `CODEX_ACCESS_TOKEN`, are preserved. The environment test covers the removal and preservation, and real command execution passed from this launch context. These internal names are not a public API: review this allow/remove boundary against a real tool run whenever upgrading Codex. A normal Agent user service does not require the desktop environment.

## Permission Mode

| Mode | approvalPolicy | sandbox | Windows override |
| --- | --- | --- | --- |
| ask | untrusted | workspace-write | windows.sandbox = unelevated |
| auto | never | danger-full-access | none |

The Windows override is supplied in `thread/start.config` and `thread/resume.config`. A sandbox failure ends the turn visibly. There is no automatic fallback to full access. Auto permits full machine access as the Agent's OS user, and is a trust decision with the same implications discussed in issue #41.

Command and file-change approval requests enter Waiting. File changes are cached from `item/started` by item and turn id, then attached to the approval as paths and full changes (including diffs and rename destinations). They are not emitted as completed chat items early. If these details are missing, the request is cancelled and the turn fails visibly instead of asking for blind approval. Decisions map to `accept`, `acceptForSession` and `decline`. Unknown server requests receive an unsupported-method error. Pending approval responses and cached changes are discarded when their turn or process ends.

## Lifecycle and events

The Task stores its Engine permanently, and the Session stores its native thread ID. Pause closes the process tree. Resume uses `thread/resume`; Agent restart recovery retains the existing Session log and continues interrupted work.

The common Engine exit callback clears the Session's process reference. Process, initialization and failed-turn errors produce `turn_end` with an error only when a turn is pending. An idle exit calls `onExit` without inventing a failed turn. The Task stays active. A subsequent user message starts a new Engine using the saved conversation ID. There are no automatic retries after an Engine error. Callbacks from stopped generations are ignored.

Codex 0.166.0 returns a new thread id before its first rollout is durable. If `thread/resume` explicitly reports `no rollout found`, the same user-triggered launch creates a replacement thread and restores the Session's recorded user messages as its initial input, including the retry. It saves the replacement id. All other resume errors surface normally; no thread is silently replaced for permission, authentication or transport errors. Replaying input before an id exists during pause or Agent restart does not append a second copy to the Session history.

The Codex adapter supports one outstanding turn per Session. Studio disables sending during that turn, and the Agent rejects concurrent messages with guidance to wait or pause. Accepting them would require queueing or `turn/steer` with separate turn and approval bookkeeping; neither is implemented here. Claude Code retains its existing streaming-input behavior. The app-server distinguishes starting a turn from steering one in the [official protocol documentation](https://learn.chatgpt.com/docs/app-server).

Only `item/completed` produces chat items. Agent messages map to text, and command, file-change and MCP items map to a tool and its result. Deltas and other item kinds are ignored. The protocol and Studio have no text-delta compatibility path.
