# Agent обновляется из Studio через собственный API, Launcher страхует откатом

Agent разделён на две части. Launcher — крошечный, ставится один раз и почти не меняется. Сам Agent заменяемый. Admin загружает сборку из Studio в Agent, та кладётся в `Agent Home/versions/<версия>`, и Launcher перезапускается на ней. Если новая версия не подтвердила работоспособность за отведённое время, Launcher откатывается на предыдущую. Перезапуск при обновлении обрабатывается так же, как перезагрузка машины: Session переходят в Interrupted и продолжаются автоматически.

## Considered Options

- **Обновление по SSH в обход Agent** — работает даже со сломанным Agent, но не подходит для локального Agent и требует, чтобы Studio знала детали установки. Годится только для разработки, не для продукта.
- **Agent сам тянет обновления из реестра** — неудобно для разработки: каждую локальную сборку пришлось бы публиковать. Можно добавить позже поверх того же механизма версий.

## Consequences

Launcher должен появиться в первой же устанавливаемой версии: добавить его на уже развёрнутые машины можно только вручную.
